Configure Razorpay

Keys are in Razorpay Dashboard → Settings → API Keys. Use rzp_test_ keys first; switch to rzp_live_ keys only when you intend to charge real money.

Required the first time. Leave blank later to keep the saved secret.
Confirms payments server-to-server if a student closes the browser early. Leave blank to keep the saved value.
Real payments will be enabled after saving valid Razorpay credentials. Students will be charged actual money through Razorpay.
Actions

Disabling or removing Razorpay switches the website back to Demo Payment Mode immediately. Existing enrollments and payment history are never affected.

How the mode is decided
  • Razorpay configured, validated and enabled → REAL PAYMENT: students pay through Razorpay Checkout; demo payments are refused by the server.
  • No valid configuration → DEMO PAYMENT: students enroll without being charged; each transaction is recorded with mode DEMO.
  • Credentials are verified against Razorpay before real payments turn on. Secrets are encrypted in the database and never shown again.

Configure SMTP

Enter the academy's email address and click Auto Configure Email — the provider, SMTP host, port, security and username are filled in for you. Only the provider credential (App Password) has to come from you.

This academy sends through a connected Google account. The SMTP fields below are not used and are kept only as a fallback — they become editable again if you disconnect Google.
The email address is the starting point — everything standard is detected from it.

The saved SMTP credential can no longer be decrypted (the server's encryption secret changed since it was stored). It cannot be recovered — enter the credential again below and click Save Email Settings. The rest of the configuration is unaffected.
Saved securely
Your email provider credential / App Password may be required for authenticated sending. For security reasons this application cannot generate or retrieve it — it is stored encrypted and never shown again.
Gmail — the recommended way
  1. Click Connect Google Account.
  2. Sign in at Google and press Allow. Google does the sign-in — this panel never sees your Google password, and no App Password is needed.
  3. You are returned here and the account shows as connected.
  4. Switch on Enable Email Sending, then Send Test Email.

The permission granted is send only (gmail.send) — this application cannot read, search or delete your mail. The authorization is stored encrypted on the server and can be withdrawn at any time with Disconnect Google Account.

SMTP — other providers & fallback
  1. Enter the sender email and click Auto Configure Email.
  2. The provider is detected from the address (Microsoft 365, Yahoo, Zoho…) or, for your own domain, from its mail (MX) records — host, port, security and username fill in.
  3. Paste the provider credential / App Password (never generated here).
  4. Test SMTP Connection → Save Email Settings → Send Test Email.
How sending is decided
  • A connected Google account with Enable Email Sending on → all system emails and website enquiries go out through Gmail.
  • No Google account, but SMTP saved and enabled → they go through that SMTP server instead.
  • Saved but disabled → nothing is sent; emails are written to the server log instead.
  • Nothing saved → the server environment (MAIL_ENABLED, MAIL_HOST…) is used if configured.
  • Tests use the values on screen even before saving, so you can verify first.
  • The SMTP credential and the Google authorization are both encrypted in the database and never shown again.
Login credentials by email

When adding a student you can tick Send login credentials by email: the account is activated and a secure, time-limited single-use password setup link is emailed to the student. Plaintext passwords are never generated or stored.

On any student page, Send Login Credentials issues and emails a fresh password setup link (valid for 48 hours). Existing passwords are never transmitted in plaintext.

WhatsApp

Receipts, invoices and messages open in WhatsApp on this computer with the message already typed — you press Send. No WhatsApp Business account, no API, no cost.
Set up once on the office computer
  1. Open web.whatsapp.com in this browser.
  2. On the academy phone, open WhatsApp → Linked devices → Link a device, and scan the QR code shown on the screen.
  3. Keep WhatsApp Web logged in on this computer. (Or install the WhatsApp app for Windows / Mac, link it the same way and choose "WhatsApp app" below.)
How sending works
  • Automation Admin → Email & WhatsApp → Payment Receipt: one click emails the receipt PDF, copies a picture of the signed receipt and opens the student's WhatsApp chat with a short line typed. Press Ctrl + V to paste the picture, then Send.
  • Invoices → WhatsApp: opens the student's chat with the invoice message and its download link. Press Send.
  • Messages to several students: each chat opens one at a time with "Open next" — press Send in each.
  • The receipt picture needs no website: it travels inside WhatsApp itself. The invoice link opens the PDF for the student without a login and works for 30 days, once the website is online.

Message History shows WhatsApp messages as Opened in WhatsApp: the message goes from the academy's own WhatsApp when you press Send, so the system never claims it as delivered.
